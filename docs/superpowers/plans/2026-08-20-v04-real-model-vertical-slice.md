# V0.4 真实模型优先封闭纵向切片实施计划

> 状态：Checkpoint A 已通过；Checkpoint B/C 离线底座已完成；当前进入 Checkpoint D 的 UI/存档/浏览器验收阶段。真实模型与世界 AI 的连续链仍需在批准边界内单独复核。
> 日期：2026-08-20
> 设计规格：[V0.4 真实模型优先封闭纵向切片](../specs/2026-08-20-v04-real-model-vertical-slice-design.md)
> 基线：`e92889c`；当前工作区含未提交的旧 V0.3 候选，实施时不得回退或覆盖他人改动

## 1. 交付策略

V0.4 不先完成大量无模型玩法再接 AI。顺序固定为：

`供应商/数据/预算决策 → 模型合同与本地网关 → T0/T1 最小真实调用 → COC 最小规则与单场景 → 真实 Keeper T2/T3 → 代表事件链 → 世界 AI 检查点 → 占卜能力 → 存档/UI → 浏览器与封闭试玩`

每项先写失败测试，再实现最小代码。默认测试使用假适配器且网络调用为 0；真实评测必须显式命令和显式预算。Checkpoint A 未证明真实模型适合 Keeper 前，不批量生产内容。

## 2. 全局约束和并行边界

- 新实现使用独立 COC/平行廷根模块与存档命名空间；旧 V0.3 文件只选择性复用幂等、快照、ViewModel 和测试思想，不原地强改为新规则。
- React 不写权威状态；模型不掷骰、不提交事件、不解锁事实、不宣布死亡/晋升/终局。
- API 密钥只进入服务端环境；不得使用 `VITE_*`、浏览器 localStorage、IndexedDB、日志、测试夹具或版本库保存。
- 默认自动化不可访问外网或读取真实模型环境变量；live eval 单独运行、单独计费、失败不自动无限重试。
- 世界 AI 与 Keeper 使用不同用途合同和 Prompt；第一版可以共享同一 ProviderAdapter，但调用、指标和失败必须分开记录。
- 不制作职业×途径剧情笛卡尔积；代表事件先覆盖公共入口和占卜家一个深度落点。
- 生产代码开始前保留当前 dirty worktree 清单；若旧 V0.3 并发修改与新模块路径重叠，先停在该文件而不是覆盖。

## 7. 测试与资源调用纪律

- 每个 Task 先运行本模块测试；Checkpoint A/B/C/D 各运行一次全量测试，最终只再运行一次构建和浏览器矩阵。
- live eval 不进入 `pnpm test`；必须使用显式命令、固定样例、最大调用数和停止条件。
- 同一失败不得无修改重复调用真实模型；先用保存的脱敏响应定位合同、Prompt、适配器或模型能力层。
- 记录真实调用的 `total/input/cached_input/output/reasoning` token，缓存和推理是子集时不得重复相加。
- 任何密钥泄漏、未授权数据传输、权威状态越权、存档损坏或 P0 回归立即停止 live eval，撤销凭据并保留回滚证据。
