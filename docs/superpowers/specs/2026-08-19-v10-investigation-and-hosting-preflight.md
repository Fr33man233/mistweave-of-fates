# V1.0 调查链与个人服务器部署预审

> 状态：产品与架构边界预审；尚未批准进入 V1.0 实现
> 日期：2026-08-19
> 上游：[版本定义与发布门](../../版本定义与发布门.md)、[产品立项书](../../../Mistweave-of-Fates-产品立项书-v0.1.md)

## 1. 已确认的产品修正

- 单条正式调查链的目标游玩时间为 **10–15 分钟或更短**，不是 30–90 分钟。
- V1.0 至少包含 **10 条不同的公共调查链**。
- 四个首发职业各至少包含 **3 条不同的职业专属调查链**，即至少 12 条职业专属链。
- V1.0 实际开放的每个超凡序列/阶位至少包含 **1 条不同的序列专属调查链**。
- 最低独立调查链数量公式为 `10 + 4 × 3 + S = 22 + S`，其中 `S` 是 V1.0 实际开放的可玩超凡序列/阶位数。若只开放观察者和猎犬各一个首次阶位，最低为 **24 条**。
- 公共、职业专属和序列专属按不同内容单元计数；同一调查链不能在三个类别中重复占位。

“专属”表示进入内容池所需的资格，不表示为每个角色或“职业 × 序列”组合分别制作：同一职业的角色无论选择哪条序列，都共享该职业的 3 条以上职业链；同一序列的角色无论来自哪个职业，都共享该序列的 1 条以上序列链。角色可访问的集合为 `公共池 ∪ 当前职业池 ∪ 当前序列池`。在最低配置下，一个已经选择单一序列的角色至少可接触 `10 + 3 + 1 = 14` 条链；项目总制作量仍为 `22 + S`，不按 `4 × S` 交叉膨胀。

这些数字是 V1.0 内容门槛，不是 MVP 门槛。MVP 先用最小真实闭环验证结构和 AI 交互是否成立，再批量生产 V1.0 内容。

## 2. 调查链的工作方式

调查链不应是预先写死的完整树状对话，也不能把事实和结局完全交给 AI 即兴决定。推荐结构是 **受约束的调查状态图 + 自由行动循环**：

### 2.1 作者预先定义的合同

- 案件前提、真实事实、关键人物、地点和利益关系。
- 可发现线索、线索来源、可信度和前置条件。
- 事件时钟、危险边界、不可逆后果和可修改的世界状态。
- 可接受的解决目标、失败条件、撤退条件和终局谓词。
- 允许 AI 使用的知识切片、语气和内容安全边界。

这些内容描述“世界真实是什么、哪些结果合法”，但不穷举玩家的每一句输入或每一步路径。

### 2.2 AI 模型负责的部分

- 理解玩家自由语言并提出结构化候选意图。
- 根据当前地点、NPC 知识、线索和已提交事件组织场景、对话与叙事。
- 在合同允许范围内提出新的调查方法或澄清问题。
- 根据已经提交的终局状态生成对应结案叙事。

模型能力决定自由度、NPC 表现和叙事自然度，但不能单独决定真相、骰点、物品、死亡或案件是否结案。

### 2.3 确定性规则引擎负责的部分

- 校验候选行动是否存在对象、满足权限和前置条件。
- 执行 D100、消耗、时间、伤势、污染、法律、关系和线索变化。
- 原子提交权威事件并推进调查状态图和事件时钟。
- 当已提交状态满足终局谓词时选择合法结局类型，再把结果交给 AI 叙述。

因此，调查链的“收束质量”会受到 AI 模型能力影响，但“收束是否正确”必须由状态合同和规则引擎决定。若完全依赖 AI 收束，将无法稳定重放、测试、迁移或防止模型改写事实。

### 2.4 公开文字游戏样例复核

样例来源为用户提供并授权直接读取的[公开对话](https://www.doubao.com/thread/xphE5TFavmungRmyy)。页面共包含 124 条消息；本次只分析第 0–119 条玩法内容，第 120–123 条项目命名讨论不纳入结论，也不复用其中的 IP 名词、设定或文本。

样例实际运行的基本回合是：玩家选择建议行动或输入组合式自由行动 → 模型直接生成场景推进 → 叙述能力或身份如何生效 → 更新文字状态栏 → 再给出 2–4 个情境建议和自由输入入口。玩家能够临时改变方法、附加限制、组合公开身份与隐秘目的，模型也能立即续写，因此其体验本质是 **AI 即兴连续叙事 + 建议选项脚手架**，不是预先写完的树状流程。

这一模式值得保留的不是“AI 可以决定一切”，而是以下交互品质：

- 玩家始终能脱离编号选项，用自然语言描述方法、目的和自我约束。
- 职业身份、能力、随身物品、已知线索、地点和 NPC 能在同一段行动中被组合使用。
- 每轮都有立即可读的场景反馈、状态摘要和下一步建议，降低纯空白输入负担。
- 模型能把同一规则结果改写成符合当前身份、地点和局势的自然叙事。

样例同时直接证明“模型兼任规则引擎”不可接受：

| 已复核失效模式 | 样例消息 | 对本项目的护栏 |
|---|---:|---|
| 玩家自行声明老鼠成功引开守卫，模型无判定接受，随后外部势力自动收网 | 30–33 | 自由输入只能提出方法；对象存在性、D100、敌方反应和援军到场均由合同与时钟裁定 |
| 写稿、提交、刊登被拆成多轮重复确认，甚至同一稿件重复“正式刊发” | 36–45、62–65、108–117 | 意图必须明确归类为 `execute / clarify / reject`；已提交动作使用事务 ID 保证 exactly-once |
| 选择编号与实际响应不一致；无效编号仍被当作合法选择 | 52–57 | 建议行动必须绑定稳定 action ID；未知编号或歧义输入必须澄清，不能猜测 |
| 物品副作用被叙事性成长永久清零，占卜逐渐变成零消耗、零风险、必然准确 | 48–55、88–103 | 能力、消耗、污染和风险上限由规则定义；叙事不得创建“百分百压制”“风险归零”等状态 |
| 图书馆、黑市和普通检索凭空提供完整高阶真相、配方、据点与敌方计划 | 67–77、96–99 | 线索只能从已定义 `ClueSource` 揭示既有 `Fact`；来源、权限、可信度和前置条件必须可追溯 |
| 稀有材料连续自动发现、取得和完美封存，没有时间、金钱、风险或失败 | 80–87 | 搜索、交易、采集和封存分别使用可验证动作、资源成本和结果档位 |
| 晋升和能力训练由模型宣布完美成功，随后能力覆盖潜行、探查和风险规避 | 100–107、118–119 | 晋升、能力范围和风险必须执行确定性前置检查与结算；能力只能修正判定，不能跳过事件 |
| 玩家要求“以公开调查掩护秘密探查”，模型先误写成发稿，纠正后仍未执行调查却直接授予全部情报 | 108–117 | `goal`、`method`、`coverIdentity` 和 `target` 分字段解析；没有发生调查动作就不能提交调查事实 |

### 2.5 最小调查链合同与回合事务

代表链进入实现前，至少需要以下字段级合同；字段名是设计基线，不要求立即锁定为最终 TypeScript API：

| 合同 | 最低字段 | 约束 |
|---|---|---|
| `InvestigationDefinition` | `id`、`eligibility`、`premise`、`durationBudget`、`startLocationId`、`factIds`、`clueSourceIds`、`clockIds`、`endingIds` | 只声明一条链可使用的权威内容范围 |
| `Fact` | `id`、`truthValue`、`visibility`、`provenance`、`unlockPredicate` | 模型不能新建或改写事实；只能叙述已经解锁的事实 |
| `ClueSource` | `id`、`locationId/entityId`、`allowedMethods`、`requirements`、`check`、`outcomes`、`revealedFactIds` | 能力不能直接生成线索；成功、带代价成功和失败分别揭示什么必须预定义 |
| `ActionIntent` | `requestId`、`verb`、`targetId`、`method`、`goal`、`coverIdentity`、`declaredAbility`、`spend` | 模型只产出候选；缺对象、越权或歧义时不执行 |
| `Resolution` | `validation`、`roll`、`outcome`、`authoritativeEvents`、`costs`、`clockDelta`、`revealedFactIds` | 由规则引擎生成并原子提交，叙事只能读取 |
| `SceneView` | `locationId`、`visibleFacts`、`visibleActors`、`suggestedActions`、`freeInputEnabled`、`riskNotices` | 建议行动是可选脚手架，不替玩家做决定 |
| `EndingPredicate` | `id`、`requiredFacts`、`requiredObjectives`、`clockBounds`、`characterConditions`、`result` | 只有谓词成立才能结案、失败、撤退或进入后续链 |

每个玩家请求只允许一次状态事务：①模型解析候选意图；②Schema、对象、权限和前置条件校验；③歧义则澄清、非法则拒绝；④需要时执行 D100 与资源结算；⑤以 `requestId` 原子提交事件；⑥生成结果反馈与叙事；⑦派生下一组建议行动。重试同一 `requestId` 必须返回原结果，不得重复扣除资源、重复刊登、重复给线索或重复推进时钟。

## 3. 全栈预审

| 维度 | 审查结论 |
|---|---|
| 用户与业务价值 | 24 条起步的短链比单条长链更适合快速尝试不同职业、路线和后果，也更能支撑公开测试与重复游玩。 |
| 产品范围 | 数量门槛与样例交互模式已确认；第一版最小调查合同已形成，仍需用一条原创代表链验证字段完整性、节奏与至少三类终局。 |
| 内容资格 | 公共链对所有角色开放；职业链按当前职业共享；序列链按当前可玩序列/阶位共享。资格采用集合并集，不生成职业与序列的笛卡尔积。 |
| UX | 单链目标 10–15 分钟或更短；玩家可自由输入，也应持续看见 2–4 个情境建议、当前线索和可解释判定。 |
| 前端 | React 只呈现场景、状态、候选行动和已提交结果；不得保存模型密钥或自行推进调查事实。 |
| 规则核心 | 调查状态图、事实、线索、时钟、终局谓词和后果由确定性 TypeScript 引擎维护。 |
| 模型边界 | AI 解析候选意图、扮演 NPC 和叙述已提交事件；不写权威状态、不掷骰、不凭叙事生成线索或终局。 |
| 数据合同 | 需要新增 `InvestigationDefinition`、`InvestigationState`、`Fact`、`ClueSource`、`Objective`、`Clock`、`EndingPredicate` 与模型上下文切片合同。 |
| 隐私与安全 | 公网模型调用必须经过服务器端网关；API Key 不得进入浏览器。需要输入限长、速率限制、日志脱敏、内容安全、CORS/CSRF 策略和滥用预算。 |
| 测试 | 每条链需离线合同校验、可达结局检查、固定种子重放和软锁检查；共享模板另做跨职业/序列矩阵，真实模型只跑小型代表性评测。 |
| 运维 | 静态站需要 HTTPS、缓存和回滚；AI 网关还需要健康检查、限流、超时、重试、成本监控、密钥轮换和无模型降级。 |
| 部署与回滚 | 保留 GitHub Pages 作为静态回退；个人服务器先部署同一静态产物，再独立增加 `/api` 网关。前端和网关必须可分别回滚。 |
| 资源效率 | 24 条以上内容不能逐条复制代码或固定树。先建设共享调查合同、内容校验器、终局可达性/软锁测试和可复用模板，再批量写内容。 |
| 最近外部里程碑 | 样例模式已提取；下一步完成 1 条不依赖固定选项树的原创 10–15 分钟调查链，并验证自由输入、exactly-once 提交、规则收束和 AI 叙事边界。 |

## 4. 工作分类

- **现在优化**：调查链合同、内容校验器、共享模板、终局可达性与软锁测试、模型上下文切片和缓存；这些是扩展到 `22 + S` 条内容前的效率基础。
- **下一原型验证**：一条原创短链接入真实自由行动解析和 AI 叙事，但事实、骰点、后果与终局仍由规则引擎控制。
- **延期**：账号、云存档、服务器权威角色卡、多人、高阶序列、大规模经济与高成本美术。
- **移除**：把每条调查链写成穷举所有输入的固定树；让 AI 直接修改状态或自行宣布未经规则确认的结局。
- **主要风险**：`22 + S` 内容生产与回归成本、AI 输出漂移、模型费用与延迟、提示词注入、公共服务滥用、个人服务器单点故障和备份不足。

## 5. 个人服务器部署选择

| 方案 | 能力 | 成本与风险 | 当前建议 |
|---|---|---|---|
| A. 静态单机网页版 | 服务器只托管 `dist`；游戏和 IndexedDB 仍在玩家浏览器 | 最低成本；换设备不共享存档；不能安全持有模型密钥 | 可立即作为 GitHub Pages 的自托管镜像 |
| B. 静态前端 + AI 网关 | 浏览器把必要状态切片发给服务器；服务器安全调用模型 | 需要 HTTPS、密钥、限流、成本和日志治理 | **推荐作为达到文字版自由交互效果的下一部署目标** |
| C. 账号 + 云存档/服务器权威 | 跨设备、可恢复、可运营；未来可支持真正不可退款角色卡 | 需要认证、数据库、备份、隐私、迁移和运维 | pre-MVP 延期，除非云存档成为测试阻塞 |

当前单机版本来就可以部署到公网网页，GitHub Pages 已经证明这一点。个人服务器带来的新增价值不是“网页才能打开”，而是自有域名、部署控制、AI 密钥安全代理、限流/成本观测，以及未来可选的云存档能力。

## 6. 资源预算与退出条件

- 设计阶段不批量编写 24 条以上内容；先用 1 条代表链验证合同、AI/规则边界和 10–15 分钟节奏。
- 真实模型评测只发送当前调查所需状态切片，不发送完整世界和历史；规则、骰点、存档和内容校验保持零模型调用。
- 批量内容生产入口：代表链可由自由输入完成，至少三类合法终局可达，无必现软锁，固定种子可重放，重复 `requestId` 不重复提交，模型失败可降级为规则摘要。
- 服务器实施入口：确认操作系统、域名/DNS、反向代理或容器能力、TLS、端口、模型供应商、月度预算、是否保存用户数据及备份/回滚方案。

## 7. GO / NO-GO

**GO：** 依据已完成的文字游戏样例复核，设计并实现一条代表性原创调查链合同；继续评估静态镜像与 AI 网关。

**NO-GO：** 现在直接批量生产全部 V1.0 调查链、把调查收束完全交给 AI，或在服务器信息、模型数据边界和安全预算未确定前上线公共 AI 接口。
