## 1. 结论与边界

V0.3 是 pre-MVP 的一个独立用户结果：在**不依赖真实模型**的条件下，玩家能走通“有结果反馈的调查 → 隐晦接触两条线索 → 主动获取材料 → 准备与首次晋升 → 在后续事件内使用能力”，并能理解失败、冲突、退出、恢复、死亡和换角；已知必现软锁为零。

它修复 V0.2 已证实的体验缺口，而非把系统验证版误称为 MVP。确定性 TypeScript 规则核心继续是唯一权威：React 只呈现 `SceneViewModel` 并提交稳定动作；未来 AI 只能给出候选意图、NPC 表达或已提交结果叙述，不能创建事实、改状态、掷骰或宣布终局。

本版不做真实 LLM、公共 AI 网关、账号、云存档、多人、战斗、完整经济、高阶路径、四路径扩展、批量案件、图像生成或高成本 UI 重制。V1.0 的 18 案件/四职业四路径和 V2.0 的 15 职业/12 完整路径均不进入本规格。

## 2. 资深全栈预审

| 维度 | 决定与理由 |
|---|---|
| 用户与业务价值 | 玩家目前只看见机械晋升；V0.3 以一个可解释、可恢复、有能力价值的调查闭环验证“调查—代价—力量”是否成立，为 MVP 外部试玩前消除结构性误判。 |
| 范围与 UX | 仅一条原创代表案件、一套最小语法、四职业通用入口、两条既有路径。主菜单、继续、换角、退出当前流程、恢复提示和行动结果是闭环的一部分，不是装饰。 |
| 前端/规则/内容/模型 | React 不保存业务真相；规则核心解析受限 `ActionIntent`、结算 `Resolution`、追加事件并投影 ViewModel；内容仅声明案件和透镜；本版无模型适配器与网络边界。 |
| 数据合同 | 增加版本化 `CaseCore` 等合同、角色姓名/性别、请求去重结果、双快照信封。所有跨引用、终局可达性、关键事实恢复入口、能力落点在内容加载前校验。 |
| 存储、迁移与回滚 | IndexedDB 使用“当前已验证快照 + 上一已验证快照”；V0.2 合法存档迁移到 V0.3，损坏或未知未来版本绝不半加载；当前损坏时只读尝试上一快照，失败进入不丢失原始记录的恢复/新局界面。 |
| 隐私、安全、原创 | 仍为浏览器本地数据、无账号/API key。姓名与性别是本地角色扮演字段，默认不上传；导出/日志不把它们发往未来模型。案件、路径、术语和文案保持原创，禁止复制受版权保护的世界、角色或文本。 |
| 测试、浏览器验收与可观测性 | 规则与迁移先做确定性单测，内容做静态校验，UI 做主流程/失败流程；浏览器验收桌面与窄屏。日志记录 schema、seed、requestId、事件序号、解析/结算码及快照版本；不记录自由文本或敏感导出。 |
| 部署、故障与回滚 | 本版不改变静态 Pages 模式。版本发布时以通过构建的 Git 提交和前一 Pages 成功部署为回滚点；本地恢复优先上一快照，不以清库掩盖数据问题。 |
| 最短外部里程碑 | V0.3 完成后仍只证明无模型的规则闭环；下一外部里程碑是 V0.5 由未参与开发者完成完整链并申请 MVP，不能跳到 V1.0。 |

### 2.1 效率优先级、预算与退出

| 分类 | 事项 | 当前成本 → 预期改进 | 验证 |
|---|---|---|---|

| optimize now | 透镜组合 | 职业×路径复制剧情会放大内容与测试 → 共享案件内核，仅插槽改变入口/信息/代价 | pairwise 覆盖四职业、两路径及高风险组合 |
| defer | 模型桩、自由语言、上下文缓存、长局城市模拟 | 此版引入会掩盖规则缺口并消耗 token → 留给 V0.4 | V0.3 不产生模型调用 |
| remove | 以自动材料、单按钮能力或批量内容充数 | 它们不验证玩家选择或力量价值 → 仅保留主动来源和一个能力落点 | 退出条件 1、2、4 |

资源预算：不增加运行时依赖、服务、模型调用或批量内容；一个案件内核、至多 3 类方法、3 个终局、2 条路径透镜、4 个职业配置。实施前必须产出 TDD 计划；实施阶段每个合同先红后绿，版本结束才运行全量测试、生产构建、迁移和浏览器矩阵。退出仅在第 11 节八项都有可复核证据时成立。

**GO：** 范围直接关闭 V0.2 已验证缺口，并先建设能降低后续内容/测试成本的合同、幂等和恢复基础。
**NO-GO：** 启动 V0.4 模型、V1.0 批量内容或 V2.0 职业/路径工作；任何一个资源归零、迁移或死亡语义缺少确定性定义时也不得开始实现。

## 3. 代表案件与最小原创内容

案件暂定名为“**雾钟下的失窃航标**”：瓦伦港雾钟在夜航前被替换，替换物会把船引向受污染的浅滩。真相在实例创建时从固定 `truthVariantId` 选定（例如走私掩盖、污染事故掩盖或误导性伪证），之后不可由叙述、职业或路径改写。

它只需要一个可进入的港区场景、3 个功能角色（值守人、船医、搬运联络人）和与事实对应的简短原创文本；不要求四城区、约 12 个地点或 12–18 名 NPC。每个变体声明：

- 三类方法：**现场勘查**、**访谈/凭证**、**职业或交易交换**；任何首发职业至少有一条通用合法入口。
- 至少三类合法终局：`report_authority`（报告并保全航标）、`repair_quietly`（修复并承担代价）、`expose_smuggling`（取得足够证据公开走私）。终局由 `EndingPredicate` 判定，而非按钮文案。
- 两个关键事实各有至少两个独立 `ClueSource` 或恢复入口：如“航标被调换”可来自现场刻痕/值守账簿；“真正去向”可来自船医证词/货运封条。来源失效、失败或资源不足时仍保留另一条路径。
- 观察者透镜可降低痕迹方法的难度或污染代价；猎犬透镜可改变追踪方法的成功阈值或伤势/理智代价。能力永不直接新增 `Fact`、跳过阶段或使终局自动成立。

## 4. 权威合同与状态机

### 4.1 最小合同

| 合同 | 最小职责与不可变条件 |
|---|---|
| `CaseCore` | `caseId`、版本、可选真相变体、关键事实、终局谓词和公共入口；不含职业×路径复制剧情。 |
| `CaseGrammar` | 可用方法槽、目标类型、前置、判定、代价、线索来源与后继；每项有稳定 ID。 |
| `Fact` | `factId`、可见性、来源事件、状态（未知/已观察/已确认）；只由已提交 `Resolution` 写入。 |
| `ClueSource` | 来源 ID、所给事实、合法方法、前置、失败替代或恢复入口；关键事实至少两源。 |
| `InvestigationInstance` | `instanceId`、`caseId`、固化 `truthVariantId`、实例 seed、时钟、事实/来源状态、已结算 requestId。 |
| `ActionIntent` | `requestId`、instance、稳定 action/method/target、可选 ability/charge；V0.3 UI 只提交受控 ID，不接受自由文本作为权威意图。 |
| `Resolution` | `resultCode`、D100 证据、时间/资源/法律/关系变化、事实变化、下一行动、终局状态；全量可投影为反馈。 |
| `EndingPredicate` | 只读取已确认事实、实例状态和明确资源/法律阈值；不读取未公开真相或 UI 状态。 |

内容校验必须拒绝：悬空引用、重复 ID、无效 seed、关键事实少于双来源/恢复、无可达终局、终局无前置、能力直接授予事实、透镜改变真相、无效职业入口和确定性软锁。

### 4.2 全流程状态机

`MainMenu → CharacterSelect/Create → CaseAvailable → CaseInstantiated → Investigating → Resolved | Ending → PathHints → MaterialAcquire → RitualPrepared → AscensionAttempted → Ascended | Restricted | Deceased → MainMenu`

- 三张槽位不可退款；活动角色最多一名。`Deceased` 永远不可激活，V0.3 无复活/继承；若无活动角色则回角色选择，若槽位也耗尽则展示墓碑与新局/本地恢复说明，绝不显示不可执行行动。
- 路径状态沿用 `hidden → hinted → trusted → prepared → ascended`，但线索以案件结果中的异常来源隐晦显示；两条均可调查，首次成功晋升锁定一条，另一条为未完成历史。
- 材料由 `MaterialAcquire` 的调查、交易、交换、采集或明确风险行动取得；每份记录 `sourceActionId`、`cost`、`risk` 和获得事件。不得自动授予。
- 首次服药仍使用既定四档结算和数值。一次角色只能有一条首次晋升；不同路径的“准备服药”并存时触发双药冲突预览，确认任一路径后另一份药与对应准备标为 `conflicted`，不可静默消费或转换。
- 普通失败不会无提示死亡。服药普通失败将该路径标为 `restricted`，保留失败原因、冷却/补救前置和一次性恢复途径；同一配方不得用新 requestId 无限重掷。灾难失败才永久死亡。具体冷却数值在实施计划前不得臆定，必须只通过已确认 V0.2 数值或显式合同补洞。
- `hp=0`：进入 `incapacitated`，当前案件动作拒绝，可通过本地明确恢复入口（治疗/退出当前案件）回到可选择状态；若无可用恢复则换角。`sanity=0`：进入 `broken`，拒绝高风险与能力/服药动作，允许离开、休整或换角；`spirituality=0`：仅禁用能力，普通调查和离开仍合法。资源不会因 UI 隐藏而永久卡死。死亡只由明确标记的灾难结算发生。

## 5. 透镜、反馈与界面投影

职业透镜是少量 `OccupationLens` 配置（许可入口、联系人、首选方法、可见信息或代价），路径透镜是 `PathwayLens` 配置（可改变的方法、判定修正或代价）。它们按案件语法的命名槽位组合：`CaseCore + Grammar + {0..1 occupation lens} + {0..1 pathway lens} + city state`。因此不制作 4×2 套案件；内容只为代表案件的兼容槽位声明一次，校验器验证组合合法性。

每次提交都投影一个不可写入的 `SceneViewModel`：

- `scene`：地点、实例阶段、可见对象与当前可尝试行动；
- `feedback`：玩家行动、方法、D100/成功等级、为什么成功/失败、时间、资源、法律/关系变化、获得/错过内容、下一合法行动；
- `caseBoard`：已确认事实、来源状态、可恢复入口与终局进度，不泄露真相；
- `profile`：姓名、性别、职业、资源、状态、路径/材料/冲突/限制摘要；
- `navigation`：继续、退出当前流程、返回主菜单、切换活动角色和恢复提示；禁止将不可执行行动投影为可点击按钮。

主信息架构为“主菜单（继续/角色档案/新档恢复）→ 活动角色与案件 → 结果反馈/案件板 → 成长准备 → 历史日志”。桌面双栏、移动单列；保留工业神秘视觉变量，不做视觉重制。确认服药、冲突处置、退出含未结算行动时均显示后果与安全返回点。

## 6. 存档、迁移、幂等与重放

根存档与 V0.3 新合同固定使用 `schemaVersion: "0.3.0"`；迁移是纯函数且分段（V0.1→V0.2→V0.3），只接收通过旧 Schema 的合法值。角色新增 `name`（非空显示名）与 `gender`（受控枚举，至少含 `unspecified`）；历史角色以明确迁移默认值填充并显示“可在档案中补全”，不猜测真人身份。

保存信封至少含 `current`、`previous`、`savedAt`、schema 版本与完整性校验值。写入顺序为：校验候选 → 将当前复制为 previous → 写入 current → 读取并再校验；失败不删除 previous。未知未来版本、校验失败、事件引用不一致或重复 requestId 结果不一致均拒绝加载并给出恢复入口。

同一个 `(instanceId, requestId)` 是幂等键：第一次事务原子写入事件、状态、`Resolution` 和去重记录；重复请求返回原 `Resolution`，绝不再次骰点、扣资源、推进时钟或生成事实。D100 仅从已固化的世界/实例 seed 与稳定 action/request 组合派生；事件日志记录 seed 引用、requestId、动作版本和状态前后游标，支持相同输入重放。
