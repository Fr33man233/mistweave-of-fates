# 跨版本自动化测试平台全栈预审与设计

> 日期：2026-08-20
> 状态：设计 GO，本地未提交
> 目标：建设一次、跨版本复用的自动化测试平台；Loop Engineering 只作为可选工作流，不成为产品开发阻断项。

## 1. 用户与业务价值

当前规则、React 界面、IndexedDB 存档和模型边界已有较多确定性单元测试，但关键玩家流程仍依赖人工启动服务、清理存档和逐步点击。随着版本增加，这会带来重复操作、漏测、串档和“组件测试通过但真实浏览器不可玩”的风险。

本建设的独立结果是：开发者可以用固定命令启动本地网页、运行隔离的桌面浏览器场景、比较玩家可见界面与只读状态投影，并在失败时得到截图、trace、控制台错误和最短复现证据。平台本身跨 V0.4、V0.5 和后续版本复用；新版本只增加场景包和迁移夹具。

## 2. 范围与非目标

### 本次范围

- 继续以 Vitest 覆盖规则、Schema、组件和存储单元测试。
- 使用 Playwright Test 建立桌面 Chromium E2E。
- 由测试框架管理 Vite 服务生命周期、固定地址、浏览器上下文和失败产物。
- 提供仅在显式测试模式启用的 `window.render_game_to_text()`，返回版本化、只读、玩家可见的最小状态。
- 覆盖 V0.4 的建档、属性/技能分配、行动预览、撤回、结算、澄清、退出和存档恢复。
- 提供 `test:e2e`、`test:automation`、`loop:fast` 和 `loop:full` 分层命令。

### 非目标

- 不修改游戏规则、数值、内容或模型权限。
- 不在默认测试中调用 DeepSeek 或读取真实 API Key。
- 不建设自动修改代码直至通过的无人监督循环。
- 不建设移动端矩阵、全浏览器矩阵、逐像素视觉基线、3D/WebGL 性能测试或云端测试农场。
- 不把旧瓦伦港场景继续作为当前版本的主要验收入口；旧规则仍由已有单元测试保护。

## 3. 玩家流程、信息架构与 UX 验收

浏览器测试从玩家可见入口进入 V0.4，不直接调用 React 内部函数。每个场景同时断言：

1. 玩家能看见并操作正确的控件；
2. 页面反馈与测试状态投影一致；
3. 没有新增 `console.error` 或未捕获页面异常；
4. 涉及存档的场景在刷新后保持一致。

当前只验收桌面视口。截图用于失败诊断和发布前代表性人工审查，不以截图替代规则断言。

## 4. 系统边界

- **React**：呈现状态并提交玩家操作；测试只通过可访问名称和稳定语义定位控件。
- **规则核心**：继续由 Vitest 验证确定性状态转换、幂等和负例。
- **内容**：E2E 只依赖玩家可见 ID 和文本，不读取隐藏真相或完整 CaseCore。
- **存储**：每个浏览器上下文使用独立本地数据；测试不加载真实玩家档案。
- **模型**：默认 E2E 只走本地确定性候选。真实模型 T1–T3 保持独立授权、独立预算、独立命令和独立记录。

## 5. 状态投影合同

`render_game_to_text()` 只在 `VITE_E2E=1` 时注册，返回 JSON 字符串。合同包含：

- 自动化合同版本、产品版本和产品模式；
- 世界 ID、固定 seed、事件游标；
- 当前角色是否存在、匿名 ID、职业、属性与技能；
- 当前可见场景、场景修订、可见对象和已确认事实；
- Keeper 流程阶段、是否存在预览、已提交 requestId 和最近结算；
- 玩家可见反馈与模型交互元数据数量。

合同不得包含 API Key、Prompt、原始自由输入、完整存档、未发现事实、隐藏真相或模型原始响应。生产构建不得注册该接口。

## 6. 数据、迁移与回滚

- E2E 使用当前 `mistweave-v04` IndexedDB 命名空间，但在独立浏览器上下文中运行。
- 每个测试使用全新的 BrowserContext，其 IndexedDB、Local Storage、Session Storage、Cache Storage 和 Cookie 与其他场景隔离；Service Worker 在测试配置中禁用。不得在应用已打开数据库后强制删库，以免制造 `blocked` 假失败。
- 固定 world seed；不依赖墙钟时间作为规则结果。
- Playwright 依赖、配置和测试文件均可通过删除新增文件并回退 `package.json`/锁文件恢复；不迁移或覆盖玩家数据。

## 7. 隐私、安全与原创内容边界

- 默认测试网络目标仅为 `127.0.0.1`；测试不得请求外部模型端点。
- 测试姓名、输入和存档全部为合成数据。
- 控制台和失败产物不得记录密钥、请求头、完整存档或隐藏真相。
- 状态投影使用白名单构造，不从世界对象递归序列化。
- 真实模型测试继续遵守既有 T0–T3 门禁，不属于 `test:automation`。

## 8. 测试、可观测性与故障恢复

- Playwright 的每个测试使用独立 BrowserContext；首版串行执行以避免 IndexedDB 和开发服务噪声。
- 本地和 CI 首次均不自动重试，避免把不稳定测试伪装成成功。
- 失败时保留 screenshot、trace 和结构化 HTML/列表报告；成功时不保留视频。
- 自动 fixture 收集 `console.error` 和 `pageerror`，测试结束统一失败。
- Vite 由 Playwright 全局 setup 通过 Node API 启动，并在 teardown 显式关闭，避免 Windows shell 子进程残留。启动失败、端口冲突或 Chromium 缺失必须给出明确错误，不复用未知外部服务。

## 9. 部署与运行边界

自动化平台只影响本地开发和未来 CI，不改变当前静态公网部署。首个外部里程碑是：在一台干净开发环境中执行一次安装后，只运行 `pnpm test:automation` 即可完成确定性测试、构建和桌面 E2E，并产生可审计报告。

## 10. 资源效率

| 成本点 | 当前成本 | 本次改进 | 验证方式 |
|---|---|---|---|
| 人工启动与点击 | 每轮重复服务启动、清档、点击 | Playwright `webServer` 与共享 fixture | 比较完整场景的人工步骤数 |
| 浏览器串档 | IndexedDB 异步清理容易遗漏 | 每测试独立 BrowserContext 和显式清理 | 连续运行两次结果一致 |
| 失败排查 | 依赖聊天或人工截图 | 失败 screenshot、trace、控制台日志 | 故意失败负例能定位步骤 |
| 每次全量 E2E | 等待成本随场景增长 | 快速层与完整层分离 | 记录 `loop:fast` 和 `loop:full` 时长 |
| 真实模型回归 | 付费且不可复现 | 默认测试完全离线 | 运行期间模型调用数为 0 |

初始预算：一个 Playwright Test 依赖、一个已验证的系统 Chrome/Chromium 通道（CI 可改用 Playwright 托管 Chromium）；首批不超过 8 个 E2E；桌面单项目；本地目标运行时间不超过 2 分钟，完整自动化不超过 5 分钟；失败产物按运行覆盖，不无限累积。

## 11. optimize now / defer / remove / risk

- **optimize now**：Playwright 基础、状态白名单、存档隔离、当前 V0.4 冒烟、失败产物、分层命令。
- **defer**：移动端、Firefox/WebKit、视觉像素基线、无监督自动修复、真实模型 E2E、性能预算。
- **remove**：每版本重建测试框架、默认截图全部成功场景、默认重试掩盖 flaky、旧瓦伦港 E01–E08 作为当前主矩阵。
- **risk**：Windows 浏览器下载与 pnpm store 权限、PWA 缓存干扰、状态投影误暴露隐藏数据、异步存档刷新竞态。

## 12. 退出条件与决策

1. `@playwright/test` 与 Chrome/Chromium 可用，配置固定桌面 Chromium 系浏览器和本地地址。
2. 测试可自行启动和关闭 Vite，不依赖人工已运行服务。
3. 状态投影仅在测试模式存在，Schema/负例证明不含禁止字段。
4. 至少覆盖建档、分配、预览/撤回、结算/反馈、澄清/不变、退出、刷新恢复。
5. 单元测试、构建和 E2E 全部通过；浏览器无新增控制台错误。
6. 连续运行两次 E2E 均通过且无串档。
7. 默认自动化过程中真实模型调用数为 0。
8. 运行手册和文档索引已更新，明确跨版本复用方式。

**GO：** 进入自动化测试基础设施实施。若 Chromium 无法安装、状态投影无法避免隐藏数据，或 E2E 无法隔离存档，则保持 NO-GO，不以人工试玩代替自动化证据。
