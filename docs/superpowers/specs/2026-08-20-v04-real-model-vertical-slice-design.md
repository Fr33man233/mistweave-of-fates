> 日期：2026-08-20

> 最近用户结果：第一份可玩新产品切片必须使用真实 Keeper；模型桩只用于自动化回归，不得作为核心体验验收证据

## 1. 版本结果与预审结论

V0.4 是旧 V0.3 之后的 **pre-MVP 产品重建切片**，不是内测、公测或正式上线。它只交付一个独立用户结果：

> 玩家在平行廷根创建符合 COC 7e 的普通人角色，进入一条可重复的危险事件链，用自然语言与真实 AI Keeper 互动；Keeper 提出可解释的行动或检定，确定性规则在玩家确认后结算，Keeper 叙述已提交结果；一次世界 AI B+ 检查点和一项序列 9 能力能改变后续方法、信息或代价；模型失败时仍可保存、退出、恢复并继续使用确定性行动。

本版不以案件数量、视觉重制或四条途径全部完成替代这个结果。真实 Keeper 是核心假设，不得延后到 MVP、V0.6 或 V1.0。

### 1.1 资深全栈增量预审

| 维度 | 决定 |
|---|---|
| 用户与业务价值 | 尽早验证“AI Keeper + 确定性 RPG”是否明显优于固定按钮文字游戏，避免在模型体验未知时批量生产内容。 |
| 产品范围 | 一张廷根地图子集、一条代表危险链、一个真实 Keeper、一个世界 AI 检查点、一条序列 9 能力；其余四途径深度和连续主/支线延期。 |
| UX | 自由输入、Keeper 提案预览、确认/修改/撤回、已提交结果、模型状态和降级提示必须处于同一任务流程；不能退化为独立聊天窗。 |
| 前端/规则/模型 | React 只投影与提交；TypeScript 规则核心决定检定、随机数、资源、事实和终局；模型只返回候选意图、对白、叙事或世界提案。 |
| 服务边界 | 浏览器不得持有供应商密钥。封闭本地阶段使用同仓库 Node 模型网关，由 Vite 开发/预览服务挂载；未来托管后端复用同一适配器合同。 |
| 数据与迁移 | 新世界使用独立存档命名空间和新 Schema；旧 V0.1–V0.3 档案原样保留为历史只读数据，不自动转换为 COC 角色。 |
| 隐私与安全 | 发送给模型的只有当前可见场景切片和最小角色投影；隐藏真相、完整存档、密钥、日志和未授权原文不得进入 Prompt。 |
| 测试 | 默认测试零真实调用；模型桩验证合同和失败路径；固定评测集与封闭试玩分别验证真实模型语义质量和玩家体验。 |
| 部署/回滚 | V0.4 只在本地或受控封闭环境启用模型；静态旧版和旧 IndexedDB 命名空间可独立回滚，模型网关可一键禁用。 |
| 资源效率 | 先验证真实 Keeper，再扩内容；世界 AI 只在检查点调用；固定测试、事件重放、场景切片和缓存避免重复 token 与人工回归。 |

**GO：** 编写并实施 V0.4；真实模型必须在第一个工程检查点完成最小调用，在第一个可玩场景中完成代表性评测。
**NO-GO：** 超出已批准最小数据边界或停止线调用模型；把密钥放入浏览器；让模型写权威状态；用模型桩宣称 Keeper 体验成立。

## 2. 范围、非目标与历史边界

### 2.1 V0.4 必须包含

1. COC 7e 八属性、技能、普通/困难/极难、奖励/惩罚骰、幸运与孤注一掷的最小可玩合同。
2. HP、`SAN：当前/上限（污染表现）`、灵性和基础伤势/失能投影。
3. 平行廷根的一个地图子集、一条原创平行事件链、2–4 个非原作核心 NPC、至少三种调查方法和两种以上合法收束。
4. 自由输入经真实 Keeper 产生 `execute | clarify | reject` 候选。
5. 行动预览、玩家确认/修改/撤回、原子提交和提交后真实 Keeper 叙事。
6. 一个世界 AI B+ 检查点，输出可验证的 `WorldProposal`，经规则批准后才持续化。
7. 占卜家序列 9 作为首条能力验证路径；能力至少同时覆盖骰子影响和信息/行动选项中的一种非骰子影响。
8. 模型超时、限流、非法 JSON、越权、断网和网关未配置时的降级、重试与恢复。
9. 真实调用的模型 ID、延迟、输入/输出/缓存/推理 token、错误和每有效行动成本记录；默认不记录玩家原始自由文本。

选择占卜家是因为它能用同一代表事件同时验证占卜信息层级、错误解释风险、能力对检定的影响和额外行动入口。它不降低 V1.0 四条途径序列 9–8 的发布门。

### 2.2 V0.4 非目标

- 四途径全部实现至序列 8、完整扮演法循环或批量能力内容。
- 原作主线、原作核心人物、第二城市、多城市旅行或全廷根模拟。
- 每回合调用世界 AI、无界自主 NPC、AI 自创途径/配方/关键真相。
- 账号、云存档、多人、PvP、公共 AI 网关或公网公测。
- 复杂战斗、完整经济、高序列、继承、复活或高成本 UI/美术重制。
- 把旧 V0.3 瓦伦港角色或观察者/猎犬自动映射为新 COC 角色与正式途径。

## 3. 全流程状态机与不可变条件

### 3.1 玩家流程

`主菜单 → 新建/继续 V0.4 档案 → COC 建角 → 平行廷根事件入口 → 场景探索/对话 → 自由输入或建议行动 → Keeper 候选 → 玩家确认/修改/撤回 → 规则结算 → Keeper 结果叙事 → 场景继续/收束 → 世界检查点 → 保存/退出/恢复`

事件链中包含一次隐晦超凡接触。测试流程可在明确内容前置满足后进入占卜家序列 9 能力场景，但不得由模型直接授予魔药、序列或事实。

### 3.2 交互状态机

```text
ready
  ├─ suggested action ───────────────┐
  └─ free text → interpreting        │
                    ├─ clarify → ready
                    ├─ reject  → ready
                    ├─ invalid → degraded → ready
                    └─ execute candidate → preview
                                             ├─ edit/withdraw → ready
                                             └─ confirm → committing
                                                            ├─ rejected by rules → ready
                                                            └─ committed → narrating
                                                                            ├─ narrative
                                                                            └─ fallback summary
                                                                                  ↓
                                                                                ready
```

世界检查点只在已提交场景结果后进入 `world_proposing → validating → committed | rejected | fallback`，不能与玩家行动提交并行修改同一状态。

### 3.3 不可变条件

- 模型响应永远是候选数据，不是权威事实。
- 随机数、成功等级、奖励/惩罚骰抵消、资源、时间、线索、死亡、晋升和终局只由规则核心提交。
- 一个玩家提交只对应一个稳定 `requestId`；重试不得重复扣费、掷骰、推进时间或写事件。
- `sceneRevision` 与候选绑定；响应返回时场景已变化则拒绝为 `stale_candidate`。
- 叙事失败不回滚已提交结果；显示确定性结果摘要并允许重试叙事。
- Keeper 不可看到角色未知事实；世界 AI 不可修改实例创建时固化的案件真相。
- 模型不可自行执行玩家主动风险行动；当前已批准的偷袭、事故和被动风险仍可由规则自动检定。
- 序列能力不限于奖励/惩罚骰，但每个效果必须映射到规则白名单并可独立解释。

## 4. 系统职责与真实模型架构

### 4.1 分层职责

| 层 | 可以做 | 不可以做 |
|---|---|---|
| React/SceneViewModel | 显示可见场景、输入、候选预览、规则结果、模型状态与恢复操作 | 直接改 HP/SAN/灵性、掷骰或解锁事实 |
| 确定性规则核心 | 校验行动、计算 COC 检定、固定 seed、事件提交、能力效果、事实/终局、幂等和重放 | 生成开放叙事或猜测玩家意图 |
| 内容包 | 定义案件真相、来源、NPC、危险、合法方法、能力钩子与世界提案模板 | 执行规则、调用模型或运行任意代码 |
| Keeper | 解释自由输入、提出行动/检定、扮演 NPC、描述场景、叙述已提交结果 | 写状态、掷骰、创造隐藏事实、替玩家确认 |
| 世界 AI B+ | 在白名单模板内组合危险、机会、传闻和临时 NPC 动向 | 新建途径、高阶设定、核心真相或无来源死亡 |
| 模型网关 | 保管凭据、限流、超时、供应商适配、响应 Schema 和脱敏遥测 | 成为第二套游戏状态源或保存完整存档 |

### 4.2 为什么必须增加本地模型网关

当前项目是 Vite 静态 React 应用。直接从浏览器调用云模型会暴露 API 密钥，也无法可靠实施限流、供应商错误归一化和日志脱敏。因此 V0.4 增加仅用于本地/封闭测试的 Node 网关，并通过 Vite 开发与预览服务挂载 `/api/model/*`。密钥使用不带 `VITE_` 前缀的服务端环境变量，只在请求时读取。

网关和游戏状态保持分离：浏览器发送最小 `ModelContextEnvelope`，网关返回候选；浏览器规则核心再次校验并决定是否提交。未来更换为托管后端时复用 ProviderAdapter 和 HTTP 合同，不把 Vite 中间件当成公网架构。

### 4.3 三个明确端点

1. `POST /api/model/keeper/interpret`：把自由输入解释为 `execute | clarify | reject`。
2. `POST /api/model/keeper/narrate`：只接收已经提交的 `ResolutionEnvelope` 和可见变化，返回叙事段落与 NPC 可见反应。
3. `POST /api/model/world/propose`：只在批准检查点接收结构化城市摘要，返回 `WorldProposal[]`。

端点分离让“行动前候选”和“行动后叙事”无法混淆。按钮式确定性行动不必调用 `interpret`；低价值结果可直接使用规则摘要，避免每次动作固定产生两次模型调用。

## 5. 数据合同

### 5.1 `ModelContextEnvelope`

必填字段：

- `schemaVersion`、`requestId`、`worldId`、`sceneId`、`sceneRevision`；
- `purpose: keeper_interpret | keeper_narrate | world_propose`；
- `playerVisibleContext`：地点、时间、可见 NPC/物体/危险前兆、已知事实 ID 与摘要；
- `characterProjection`：姓名、职业、可见条件、相关技能、HP/SAN/灵性和已解锁能力；
- `allowedActionCatalog`：当前规则允许的目标、方法、技能、能力、代价类型和风险等级；
- `conversationWindow`：受限最近对话与结构化摘要；
- `contentPackId`、`rulesetVersion`、`promptVersion`。

明确禁止字段：供应商密钥、完整存档、隐藏事实正文、未发现线索、完整事件日志、其他角色私有状态和与当前行动无关的原著材料。

### 5.2 `KeeperInterpretation`

```ts
type KeeperInterpretation =
  | { kind: 'execute'; targetId: string; methodId: string; skillId: string; abilityId?: string; proposedDifficulty: 'regular' | 'hard' | 'extreme'; riskIds: string[]; rationale: string }
  | { kind: 'clarify'; question: string; allowedAnswerHints: string[] }
  | { kind: 'reject'; reasonCode: string; explanation: string; suggestedAlternatives: string[] };
```

模型只能引用 `allowedActionCatalog` 已存在的稳定 ID。未知 ID、重复字段、额外状态变化、隐藏事实和未声明工具调用全部拒绝，不做模糊纠正后自动执行。

### 5.3 `ActionPreview` 与提交

规则核心将 `KeeperInterpretation.execute` 转换为 `ActionPreview`：

- 展示目标、方法、技能、难度、奖励/惩罚来源、能力影响、资源/时间成本和可能风险；
- 标记 `playerConfirmationRequired: true`；
- 包含 `requestId`、`payloadHash`、`sceneRevision` 和稳定 seed 输入；
- 玩家修改后生成新 `requestId`，撤回不产生事件。

确认后，规则核心一次性返回 `nextState + ResolutionEnvelope + CommittedEvent[]`。模型不参与这次事务。

### 5.4 `ResolutionEnvelope`

只包含玩家可见且已经提交的事实：行动、检定值、骰点、成功等级、奖励/惩罚来源、能力效果、资源/时间/关系/场景变化、可见新事实、下一合法行动和稳定事件引用。Keeper 只能改变表达方式，不能改变任何字段。

### 5.5 `WorldProposal`

```ts
type WorldProposal = {
  proposalId: string;
  templateId: string;
  subjectIds: string[];
  triggerId: string;
  proposedParameters: Record<string, string | number | boolean>;
  visibleForeshadowing: string;
  expiresAtCheckpoint: number;
};
```

内容包预先声明合法 `templateId`、主体类型、参数范围、前置、互斥、成本和最大持续时间。规则校验后产出 `committed` 或带稳定原因的 `rejected`；临时 NPC/传闻在未提交前保持 `ephemeral`。

## 6. COC、序列能力与代表事件

### 6.1 COC 规则最小面

新 Schema 使用 COC 7e 的 `STR/CON/SIZ/DEX/APP/INT/POW/EDU`，旧 `physique/agility/perception` 等字段不直接迁移。V0.4 只实现本事件链实际需要的技能和成长入口，但公式、成功等级、奖励/惩罚骰、幸运与孤注一掷必须完整一致，不能用旧原创 D100 冒充。

人物档案建角不把属性和技能全部系统定死：四个世俗职业各自提供固定属性模板，模板之外保留 100 点属性自由分配且允许剩余；职业技能点 = 教育值 × `20`，兴趣技能点 = 智力值 × `10`，职业点只能投入职业技能池，兴趣点可投入任意已列出的技能。新建档案只提供女性/男性选项，旧快照中的其他性别值仅用于兼容解析且不改变属性模板。技能初始值与上限仍由确定性规则校验，不允许模型擅自改写技能。

灵性上限使用已批准公式：

`floor(currentPOW / 5) + sequenceBaseBonus + pathwayRankBonus + actingMilestoneBonus + event/item modifiers`

SAN 将污染作为显示状态合并投影，内部事件仍记录来源和恢复类别；扮演进度与失控同理。V0.4 不单独显示污染条或失控条。

### 6.2 能力效果白名单

V0.4 的能力规则至少支持：

- `dice_modifier`：奖励骰/惩罚骰抵消；
- `difficulty_shift`：在内容允许范围内改变难度；
- `information_tier`：成功后获得更高层级的可见解释；
- `action_unlock`：出现额外合法调查方法或目标；
- `skill_or_method_substitution`：用批准能力替换技能或方法；
- `cost_modifier`：改变灵性、时间、暴露或 SAN 风险；
- `auto_success`：只对明确标记为基础且能力充分覆盖的行动启用，高威胁场景禁止。

占卜家序列 9 的本版能力至少选择一个 `dice_modifier` 和一个 `information_tier` 或 `action_unlock` 落点。所有能力效果由内容钩子和规则白名单决定，Keeper 只能建议玩家使用。

### 6.3 代表事件的最小原创边界

- 地点：廷根地图的一个可独立游玩子区，不重演原著事件。
- NPC：2–4 名平行世界原创功能角色，不出现原作核心人物或替代其主线职责。
- 危险：普通人可以先用职业/社会/调查手段应对，但拖延、错误判断或接触超凡会产生可解释升级。
- 真相：实例创建时固化；至少一个关键事实有两个来源或一个失败恢复入口。
- 方法：现场观察、社交/访谈、职业技能或交易至少三类。
- 收束：至少两种合法结局和一种带代价继续状态；普通失败不关闭全部流程。
- 超凡接触：隐晦且通过来源/前置解锁；模型不得因为玩家直接说出途径名称就跳过发现过程。

## 7. UX 与 SceneViewModel

主界面仍是游戏场景，不是聊天产品：

- 场景区显示地点、NPC、危险前兆和 Keeper 叙事；
- 行动区持续显示 2–4 个规则建议行动、自由输入和模型处理状态；
- 候选预览必须允许确认、修改和撤回；主动风险默认不得跳过预览；
- 结果区显示检定、骰点、奖励/惩罚来源、能力效果、资源/时间变化及 Keeper 叙事；
- 模型状态区区分 `连接中/解释中/等待确认/结算中/叙事中/已降级`，防止重复点击；
- 角色、世界、途径、主菜单、退出、继续、换角和恢复继续使用确定性 ViewModel。

同一模型请求完成前禁用重复提交但允许取消。取消只忽略候选，不取消已经提交的规则事务。超时或非法响应后保留玩家原输入，提供“重试解释”“改用建议行动”“返回场景”，不能出现死按钮。

## 8. 模型准入、隐私与安全

### 8.1 供应商决策门

首个供应商与准确模型已由用户选定为 DeepSeek `deepseek-v4-flash`，官方协议、价格、隐私与准入状态见[DeepSeek V4 Flash 模型准入记录](../../model-evals/2026-08-20-deepseek-v4-flash-onboarding.md)。API Key 已由用户持有，不得在聊天或仓库中提供。

用户已明确允许发送最小玩家可见场景、COC 角色投影、封闭玩家行动输入和已提交可见结果；已关闭将输入用于训练，并批准 T1/T2/T3 分别为 1次/¥1、50次/¥5、200次/¥20 的停止线。源码、完整文档/存档、隐藏真相、未发现线索和个人敏感数据始终禁止发送。

真实调用前仍必须由用户批准：

1. 是否允许供应商处理并按其政策保留输入；
2. 可发送的数据范围，尤其是项目原创内容与玩家自由输入；
3. 单次评测和封闭试玩的费用上限；
4. 凭据注入位置和轮换/撤销方式。

本次只使用供应商官方文档核对端点、协议、结构化输出、上下文/输出上限、推理参数、价格、限流和弃用状态。无法确认的能力标记未知；模型变更必须重新通过准入门。

### 8.2 T0–T3 渐进验证

- `T0`：零付费离线 Schema、Prompt、缺失密钥、超时、错误脱敏和假适配器验证。
- `T1`：一次固定无敏感文本的最小真实调用，确认实际模型 ID、结构化结果、token 和无密钥泄漏。
- `T2`：小型脱敏代表集，验证 `execute/clarify/reject`、越权拒绝、延迟和成本。
- `T3`：本地可回滚真实场景实验，允许发送已批准的最小游戏切片；不允许模型直接外部写入或状态提交。

任一级失败不得跳级或静默替换模型/传输。T1 之前仍可完成离线代码，但 V0.4 体验不能标记通过。

2026-08-20 的独立修复后 T1 复测只发送固定无敏感文本，实际返回模型为 `deepseek-v4-flash`，安全元数据为 `input/cached_input/output/reasoning_output/total=68/0/43/0/111` tokens、`1045ms`；候选键集合为 `allowedAnswerHints/kind/question`，但 `kind: clarification` 不满足严格 `clarify` 合同。该失败记录保留不改写。随后用户新授权一次独立精确枚举 T1 复测：系统 Prompt 固定 `kind` 必须为小写 `clarify`（Prompt `t1-clarify-v2`），实际模型返回严格 `clarify`；安全元数据为 `input/cached_input/output/reasoning_output/total=106/0/36/0/142` tokens、`997ms`。该成功调用没有自动重试、模型/供应商切换或游戏内容发送，也不记录原始候选正文或密钥。Checkpoint A 已通过；进入 Checkpoint B 仍等待用户明确决定。

Checkpoint B 的首个 T3 最小场景随后得到用户的明确数据边界授权：向 `deepseek-v4-flash` 发送廷根河岸最小可见场景、玩家行动和已提交确定性结果，共 2 次调用。`keeper_interpret` 返回合法 `execute`（`input/cached/output/reasoning/total=202/0/63/0/265`，`1149ms`）；`keeper_narrate` 返回合法叙事 JSON（`207/0/33/0/240`，`805ms`）。未发送源码、完整存档、隐藏真相或个人数据，原始正文不落盘。该结果证明真实模型结构化纵向链路成立；叙事事实一致性的人工封闭试玩仍是后续阻断项。

### 8.3 Prompt 与输出安全

- 系统指令由版本化模板生成，玩家文本和内容文本始终作为不可信数据分隔。
- 模型不获得 shell、文件、网络浏览、数据库写入或任意工具权限。
- 输入限长；控制字符、超长历史和未授权字段在网关前拒绝或裁剪。
- 输出只接受严格 Schema；未知字段默认拒绝，错误信息不回显密钥、Prompt 或供应商原始请求头。
- 默认遥测保存结构化元数据，不保存原始自由文本和完整模型输出；调试原文必须显式开启、仅本地、可一键清除。

## 9. 存档、重放与恢复

- 新 IndexedDB 名称、根 Schema 和 `contentPackId/rulesetVersion/modelContractVersion` 与旧档隔离。
- 权威事件日志不保存供应商密钥或依赖模型才能解释的隐含状态。
- 可选保存经脱敏的 `ModelInteractionRecord`：请求 ID、用途、模型 ID、Prompt 版本、上下文哈希、结果类型、延迟、token、错误码和引用的权威事件 ID。
- 存档恢复后不重放历史 API 调用；用已提交事件重新投影场景。未完成候选一律丢弃并提示重新提交。
- current 损坏时恢复 previous；两者均损坏时拒绝并保留原始记录；旧命名空间只读展示“历史版本存档”。
- 模型网关不可用时，确定性建议行动、规则摘要、保存、退出、切换角色和恢复仍可用。

## 10. 测试、浏览器验收与模型评测

### 10.1 默认零调用测试

- COC 公式、成功等级、奖励/惩罚骰、幸运、孤注一掷和资源边界。
- 模型请求/响应 Schema、未知 ID、隐藏事实、越权状态变化、超长输入和 Prompt 注入负例。
- `requestId + payloadHash + sceneRevision` 的重复、冲突和过期响应。
- 模型超时、断网、429/5xx、非法 JSON、空响应、叙事失败和世界提案拒绝。
- 占卜能力的骰子与非骰子效果，以及高威胁衰减/禁用。
- 固定 seed 事件链、两种收束、失败恢复、保存/退出/恢复和旧档隔离。

### 10.2 真实模型评测

首个代表集至少包含：直接合法行动、歧义目标、非法行动、越权要求、提示注入、能力使用、未知对象、风险未确认、隐藏真相诱导和模型应拒绝的事实创造。记录：

- `execute/clarify/reject` 分类与 ID 映射正确率；
- 非法权威状态变化接受数，退出条件为 `0`；
- Schema 首次通过率和修复/重试次数；
- p50/p95 延迟、失败率和每有效行动成本；
- Keeper 叙事与已提交事实矛盾数，退出条件为 `0`；
- 玩家对风险、检定和后果的理解。

MVP 的 `≥80%` 自由行动正确执行或合理澄清仍是最低门。V0.4 首轮如果未达标，应修正合同、Prompt 或模型选择，不用增加按钮掩盖失败。

### 10.3 浏览器矩阵

1. 桌面网页宽度完成建角、自由输入、候选预览、确认、结果、退出和恢复；移动端适配与矩阵延期至 V1.0 前后，不作为 V0.4 退出条件。
2. 重复点击、返回、刷新和切换角色不产生重复事件。
3. 模型未配置、连接中、超时、非法候选、叙事失败和世界提案拒绝均有可见恢复入口。
4. 占卜能力必须存在于具体任务流程，并能明确改变信息或选项，而非独立面板按钮。
5. 至少一次真实 Keeper 和一次真实世界 AI 调用在受控环境完成并记录模型/成本证据。

## 11. 资源预算与效率基础

| 成本点 | 当前成本 | V0.4 决定 | 预期改进 | 验证 |
|---|---|---|---|---|
| 模型体验未知 | 批量内容可能返工 | Checkpoint A 就做真实模型 T1/T2 | 在内容扩张前发现交互问题 | 代表集与单场景结果 |
| 每动作双调用 | 解释+叙事可能翻倍成本 | 按钮不解释；低价值结果用规则摘要；重要提交才叙事 | 真实 Keeper 保留在有体验价值处 | 每 100 动作调用数 |
| 世界 AI | 每回合模拟昂贵且漂移 | 只在一个明确检查点调用 | 控制 token 与状态风险 | 世界调用/玩家动作比 |
| 长上下文 | 回合增加导致 token 膨胀 | 可见切片、结构化摘要、按 ID 引用、上下文哈希缓存 | 50 回合输入规模趋稳 | 10/25/50 回合比较 |
| 模型回归 | 重复真实调用贵且不可复现 | 假适配器、固定样例、录制脱敏响应、事件重放 | 默认测试零付费 | 默认测试网络调用为 0 |
| 本地启动 | 双进程/密钥配置增加手工步骤 | 单命令挂载网关；启动时自检但不发请求 | 降低人工验收准备 | 新环境启动步骤数 |

初始真实调用预算在供应商选择时确认；未获批准前默认为零付费调用。预算必须分别限制 T1、T2 和封闭试玩，不允许测试失败后无界重试。默认自动化测试永远不读取真实密钥。

## 12. V0.4 退出条件

1. 新 COC Schema、历史存档隔离和确定性事件重放通过。
2. 真实模型 T0–T3 逐级通过；至少一次真实 Keeper 单场景调用，不以模型桩替代。
3. 自由输入只产生 `execute | clarify | reject`，代表集至少 80% 正确执行或合理澄清。
4. 连续代表流程中模型越权状态提交、隐藏事实泄漏和叙事事实矛盾均为 0。
5. 玩家能预览、修改、撤回和确认；重复/过期响应不重复结算。
6. 一个世界 AI 检查点产生合法提案，非法提案可解释拒绝，模型失败不阻塞流程。
7. 占卜家序列 9 能力在具体事件内产生一个骰子效果和一个非骰子效果，并保留高威胁限制。
8. 桌面网页完成建角、事件、模型交互、保存、退出和恢复；无已知必现软锁。移动端矩阵不属于 V0.4 必需证据。
9. 模型 ID、Prompt 版本、延迟、分项 token、失败率和每有效行动成本可追溯，原始玩家文本默认不落盘。
10. 真实模型禁用后仍可用确定性建议行动完成或退出代表事件，旧 V0.3 存档未被覆盖。

只有十项全部有自动化、真实模型和浏览器证据时，V0.4 才能称为“真实模型封闭纵向切片通过”。它仍不等于 MVP。

## 13. optimize now / defer / remove / risk

- **optimize now**：模型合同和网关、真实 Keeper 早测、COC 最小规则、请求幂等、场景切片、失败降级、固定评测、成本遥测、单命令本地启动。
- **defer**：其余三条途径、序列 8、长篇主线、完整扮演循环、托管网关、账号/云档、继承、多城和高成本视觉重制。
- **remove**：浏览器直连云模型、模型桩作为体验证据、每动作固定双模型调用、世界 AI 每回合模拟、模型直接写状态、继续修旧 V0.3 代表新产品。
- **risk**：DeepSeek 云端数据处理与保留、真实模型延迟和漂移、原著内容公开资格、占卜信息泄密、Node 网关从本地迁移到未来托管环境的差异。

## 14. 最终 GO / NO-GO

**GO：** 进入 [V0.4 实施计划](../plans/2026-08-20-v04-real-model-vertical-slice.md)，按已批准的 DeepSeek V4 Flash 边界先完成离线合同和最小真实模型验证，再扩展规则、事件、世界 AI 与能力内容。
**NO-GO：** 超出批准数据/费用边界执行 T1–T3；在真实模型单场景失败时继续批量开发四途径或连续内容；在版权/授权未解决前公网发布。
