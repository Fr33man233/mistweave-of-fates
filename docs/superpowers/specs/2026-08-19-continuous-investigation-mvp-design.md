# 连续调查规则原型：扩展设计

## 目标

把当前一次点击结算的三例案件升级成可持续保存的单城市调查规则原型，用于验证案件阶段、选择、时间和后果状态能否支撑后续体验开发；本设计不等同于达到项目 MVP。

## 范围

### 交付

- 三例案件均具备：接触、调查方法选择、结算三个阶段。
- 每次方法选择结算 D100，更新时间、线索质量、NPC 警觉或法律关注。
- 界面展示当前场景、任务阶段、角色状态、事件日志和可执行行动。
- 提供自由行动输入框；V0.1 只做关键词本地降级解析，并在无法理解时明确拒绝。
- 每次行动后把完整 Game 状态写入 IndexedDB；启动时恢复。
- 没有网络、没有模型 API 时，三个案件均可走到结算。

### 不交付

- 角色创建、职业完整经济、魔药、晋升、真实 LLM、图像生成、多人、战斗、死亡继承。

## 架构

`App -> local action parser -> GameEngine -> committed event -> Game state -> IndexedDB -> UI projection`

- `GameEngine` 是唯一改变权威状态的模块。
- 每个案件由 `CaseDefinition` 定义阶段、行动、技能阈值、消耗和后果。
- 自由输入只映射到已定义的行动 ID，不能创建事实或绕过 D100。
- 存档保存状态和事件日志；加载失败时创建新局，不阻断试玩。

## 数据与行为

- `CaseState`：`available | active | resolved`，以及当前阶段和已选方法。
- `ActionResult`：包含判定层级、耗时、线索、警觉变化、法律变化与叙事摘要。
- 每案至少两种调查方法：安全但线索弱，或冒险但线索强。
- 完成一个案件不会移除其他案件；世界时间和角色风险为共享状态。

## UI

- 顶部：城市、地点、时间。
- 左侧/上方：理智、灵性、污染、警方关注。
- 中部：当前案件、场景文字、阶段和行动按钮。
- 右侧/下方：不可变事件日志与获得线索。
- 底部：自由行动输入与解析结果。

## 验收

1. 新局能依次完成三个案件，每案至少有一次中间选择。
2. 固定种子下相同行动序列产生相同事件日志。
3. 冒险与安全行动至少在时间、线索或风险之一产生不同结果。
4. 刷新/重新加载后恢复当前案件阶段、世界时间、线索和事件历史。
5. 无法识别的自由输入不会改变世界；已识别关键词会映射到合法行动。
6. 自动化测试、TypeScript 编译和 PWA 构建均通过。

## 资源效率与风险

- 当前成本：仅本地规则和少量原创文本，无模型调用、无图片生成、无服务端。
- 预期收益：先验证可玩性再投入角色创建与超凡内容，避免高内容成本返工。
- 主要风险：三案内容仍较短；通过阶段化、共享状态和试玩问卷收集定性反馈，而不是把内容规模误当作系统验证。

## 决策

**GO**：范围足以形成早期规则与交互反馈，且不改变已确认的 V0.1 技术路线；是否达到 MVP 仍按独立发布门验收。
