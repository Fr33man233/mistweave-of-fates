# V0.2 首次晋升体验版设计

> 上游基线：[V0.1 验收与发布记录](../../../Mistweave-of-Fates-V0.1验收与发布记录.md)、[V0.1 规则与内容数据合同](../../../Mistweave-of-Fates-V0.1规则与内容数据合同.md)、[V0.1 实现计划](../../../Mistweave-of-Fates-V0.1-TypeScript实现计划.md)

## 目标

让玩家完整体验从普通职业角色创建、日常调查、隐晦接触两条超凡线索、收集材料并完成首次魔药晋升的闭环；该版本用于收集真实玩家对成长节奏、风险和力量价值的反馈。

## 固定范围

- 三张角色卡槽位；死亡角色永久失效、无复活或继承。
- 四个初始职业：药房学徒、记者、警探、码头工人。
- 两条原创首发途径：观察者与猎犬。
- 每条途径仅实现首次晋升与一个可加注能力。
- 现有三案作为共同前置；新增可信来源、材料/仪式、服药三个节点。
- 不实现多人、战斗、完整经济、图像生成、真实 LLM 或高阶序列。

## 成长流程

1. 玩家创建一名普通职业角色，消耗一个角色槽位。
2. 先完成至少三次有效日常、职业或城市事件。
3. 系统根据职业、初始意愿、实际选择、风险偏好和技能使用，投放观察者与猎犬两条隐晦线索。
4. 玩家可并行调查两条线，也可暂时完全不碰超凡内容。
5. 每条线依次经历：异常线索、可信来源、材料与仪式、服药抉择。
6. 玩家在理解能力方向、不可逆改变、失控/死亡风险后，主动选择一条服药。
7. 服药完成后该角色锁定该途径；另一条线保留为未完成记录。

## 力量与数值

| 状态 | 灵性 |
|---|---:|
| 普通人 | 5/5 |
| 首次晋升成功 | 8/8 |

- 观察者：痕迹感知，修正观察判定或揭示更深异常信息；每次加注提高污染风险。
- 猎犬：危险追迹，修正追踪或危险应对判定；每次加注提高伤势或理智风险。
- 两种能力基础消耗 1 灵性，判定前可加注两次；总消耗为 1–3 灵性。
- 加注必须在骰点前声明；归零时不能发动能力；能力不直接生成线索或跳过事件阶段。

## 风险与死亡

- 日常任务和一般调查失败只造成时间、伤势、法律、关系或线索损失。
- 明确标记的异常现场、危险材料获取和服药/仪式失败可造成死亡。
- 首次服药依次执行前置条件检查、准备质量计算、D100 判定和结果落地。
- 结果为成功、带代价成功、失败、灾难失败；灾难失败导致角色死亡。

## 测试版与正式版

V0.2 将“3 次有效事件后出现线索、2–4 次事件内逐步投放”作为压缩体验节奏。正式版沿用同一结构，但扩大日常积累、线索节点、材料稀缺性、势力竞争和过程死亡风险。

## 数据与 UI

- 存档新增角色档案、剩余槽位、死亡角色、初始意愿、线索权重、途径状态、材料、仪式准备和晋升结果。
- UI 新增角色创建、角色卡选择、双线索调查板、材料/仪式清单、风险预览、服药确认与死亡档案。
- 所有状态仅由权威事件写入；叙事和后续 AI 接口只能读取已授权切片。

## 验收

1. 四职业均可创建，并正确消耗三个角色槽位。
2. 两条线索按行为权重出现且可并行调查。
3. 每条途径可完成一次材料、仪式和服药链。
4. 首次成功晋升后灵性从 5/5 变为 8/8，能力在 1–3 灵性加注规则下可重放结算。
5. 风险行动与服药灾难失败能永久失效角色卡；一般调查不会无预警死亡。
6. 刷新后角色、线索、材料、风险与事件日志完整恢复。
7. 全量自动化测试、生产构建和 GitHub Pages 部署通过。

## 效率与发布判断

以既有案件、状态机、D100 和 IndexedDB 为基础扩展，避免重复实现世界、存档与调查系统。只有上述首次成长链完成且试玩反馈显示玩家理解风险、愿意追查线索，才进入 V1.0 的更大内容与发布准备。

## V0.2 全栈预审与执行门

| 维度 | 决定 |
|---|---|
| 用户与业务价值 | 优先交付“创建角色至首次晋升”的单次完整体验，用于获得真实玩家对风险、节奏与力量价值的反馈。 |
| 范围与 UX | 只新增角色档案、双线索、仪式、服药、能力与死亡档案；界面必须让玩家在高风险操作前看见条件与后果。 |
| 前后端与模型边界 | TypeScript 规则核心拥有全部状态和 D100；React 仅呈现/提交；不接入真实 LLM、后端或网络依赖。 |
| 数据与安全 | 只把本地游戏状态保存于 IndexedDB；不收集账户、个人信息或凭据；存档按版本校验并在解析失败时保留安全降级入口。 |
| 测试与运维 | 每个规则模块先红后绿；发布前运行全量测试、生产构建和 Pages 试玩；发布失败可回退到上一 GitHub 提交与 Pages 成功部署。 |
| 资源效率 | 当前成本是重复实现档案/存档和不确定性调试；复用 V0.1 的事件、D100、存档与现有测试夹具。预期减少新模块以外的重复实现；以新增单测、全量测试和构建通过验证。 |
| 预算与退出条件 | 不新增依赖、服务端或模型调用；完成本规格 7 条验收条件、GitHub Pages 可试玩并得到首批反馈后结束 V0.2，未达成则不扩大到 V1.0。 |

**GO**：该版本直接服务于真实玩家反馈，不包含会显著增加维护成本的多人、模型或高阶内容。
