# Mistweave of Fates（灰雾织命）：版本定义与发布门

> 状态：当前版本成熟度的统一判断依据
> 更新日期：2026-08-19
> 适用范围：V0.x、MVP 与 V1.0 的命名、立项和验收

## 1. 三种成熟度不是同义词

- **规则原型/系统验证版**：证明规则、状态、存档、界面或部署链能够运行。自动化测试和线上冒烟可以证明“系统可执行”，不能单独证明“玩家体验闭环成立”。
- **MVP**：用最小但真实的产品体验验证核心假设。它必须让外部玩家走通调查、后果、成长和自由行动，并留下可复核的体验与连续性证据；公开部署不等于达到 MVP。
- **V1.0**：MVP 通过后，第一个可稳定支持的公开单人正式版。它不是完整世界、多人版或最终美术版，但必须具有清楚的开始、进行、失败、恢复和结束路径，以及可维护的兼容、发布与回滚能力。

## 2. 当前版本判定

| 版本 | 正确定位 | 已证明 | 尚未证明 |
|---|---|---|---|
| V0.1 | 连续调查规则原型 | 确定性 D100、事件提交、三案基础状态、IndexedDB 与 Pages 发布 | 完整调查体验、自由行动质量、持续世界和 MVP 假设 |
| V0.2 | 首次晋升规则系统验证版 | 四职业入口、三槽档案、双路线状态机、自动材料准备、D100 晋升、能力消耗、永久死亡、存档与线上部署 | 有反馈的日常调查、主动材料获取、隐晦线索体验、事件内能力价值、完整失败/冲突/恢复路径 |
| MVP | 尚未达到 | 已具备确定性规则和本地持久化基础 | 下列 MVP 发布门尚未全部通过 |

V0.2 的首轮反馈已经证明系统验证版具有反馈价值，但反馈同时证明“完整玩家体验闭环”尚未成立。后续文件不得用测试数量、构建成功或 Pages 可访问替代 MVP/体验验收。

## 3. MVP 发布门

MVP 只有在以下条件全部有证据时才能标记“达到”：

1. **角色与完整主循环**：玩家创建包含姓名、性别、四种首发职业之一和初始意愿的角色；完成“有结果反馈的日常/职业调查 → 隐晦双线索 → 主动获取材料并准备仪式 → 首次晋升 → 在后续任务中使用能力”的连续流程。
2. **后果与恢复**：成功、普通失败、带代价成功、死亡、双药冲突、失败后的服药限制、退出/返回和理智等资源归零后的恢复路径均有确定性规则，不存在已知必现软锁。
3. **行动与叙事边界**：建议行动与始终可见的自由输入并存；至少一个受支持的模型适配器只解释候选意图和叙述已提交结果，不能写权威状态。无法执行或歧义行动必须拒绝或澄清。
4. **持续世界证据**：地点、NPC、证据、时间和法律后果能跨事件持续并影响后续选择；关闭和恢复存档后保持一致。
5. **量化退出条件**：测试者能在不改存档时完成至少 30 个游戏日或一条超自然线索链；连续 50 回合无权威状态与叙事矛盾；至少 80% 的代表性自由行动被正确执行或得到合理澄清。
6. **工程与外部试玩**：确定性规则、数据合同、迁移、构建、部署和回滚验收通过；至少一轮由未参与开发的玩家完成核心流程，并能理解主要判定、风险和后果。

任一条件只有设计、代码或自动化测试而没有对应体验/连续性证据时，应标记“部分达到”，不能整体宣称 MVP。

## 4. V1.0 定义

V1.0 定义为：**在 MVP 核心假设已经由外部试玩验证后，可稳定公开支持的原创单人版本。** 最低发布门为：

1. MVP 六项发布门全部通过，MVP 试玩发现的 P0/P1 问题和核心流程阻断已关闭。
2. 单条正式调查链目标为 10–15 分钟或更短；至少提供 10 条不同的公共调查链、四个首发职业各 3 条不同的职业专属调查链，以及每个 V1.0 实际开放的超凡序列/阶位至少 1 条不同的序列专属调查链。职业链由同职业角色共享且不受所选序列影响；序列链由同序列角色共享且不受职业影响。角色按 `公共池 ∪ 当前职业池 ∪ 当前序列池` 取得资格，不生成职业×序列组合内容。最低独立内容量为 `22 + S` 条，`S` 为可玩序列/阶位数；最低配置下单个已选序列角色至少可接触 14 条。首次晋升后的能力必须在相应事件中产生可理解的收益与代价。
3. 新玩家可以依照说明完成启动、模型配置、建角、游玩、保存、退出、恢复和反馈；依赖或模型不可用时有可解释的降级路径。
4. 角色、地点、NPC、证据、法律状态和事件日志具有稳定的数据合同、迁移测试与上一版本回滚路径；50 回合连续性和资源成本有实际记录。
5. UI 在桌面和移动宽度上清楚、简便、可访问，足以支撑完整流程；V1.0 前不以高成本美术采购或系统性视觉重制作为发布条件。
6. README、版本说明、已知限制、隐私/凭据边界、许可证、发布工作流和线上冒烟均有可追溯证据。

多人、PvP、服务器权威、多城市、完整经济、高阶路径、复杂战斗、复活/继承和高成本美术不是 V1.0 的默认门槛；如要纳入，必须另做全栈预审并证明不会拖延核心单人正式版。

正式调查链采用“受约束的调查状态图 + 自由行动循环”，而不是穷举玩家输入的固定树。作者定义事实、线索、时钟、风险和合法终局；AI 负责候选意图、NPC 与叙事；确定性规则引擎负责判定、状态提交和终局谓词。详细边界见[V1.0 调查链与个人服务器部署预审](superpowers/specs/2026-08-19-v10-investigation-and-hosting-preflight.md)。

代表性调查链验收必须覆盖组合式自由行动、无效编号、歧义目标、重复请求、资源不足、能力失败和模型不可用。每次输入只能产生 `execute`、`clarify` 或 `reject` 之一；同一请求不得重复扣除资源、推进时钟或提交线索，叙事不得泄露尚未满足来源和前置条件的事实。

## 5. 下一步约束

下一版本仍属于 **V0.x 的 pre-MVP 收敛阶段**。其首要任务是把 V0.2 的机械流程升级为真实调查与力量价值闭环，并关闭已记录的六项试玩缺口；在完成新的全栈预审、数据迁移设计和可验收范围前，不直接启动 V1.0，也不以增加内容数量代替核心体验验证。
