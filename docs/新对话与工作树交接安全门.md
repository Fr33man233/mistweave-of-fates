# 新对话与工作树交接安全门

> 状态：项目强制规则
> 生效日期：2026-08-20
> 事故来源：V0.3→V0.4 交接连续两次落入旧基线，第二次还提前消耗一次不可重复的真实模型调用。

## 1. 适用条件

只要源任务存在未提交或未跟踪文件，且新任务需要继续使用这些文件，本安全门必须执行。聊天中的口头摘要、相对路径或“startingState=working-tree”参数都不能替代工作区身份验证。

## 2. 创建方式

1. 默认使用当前任务的 `same-directory` fork，使新任务共享源任务的精确工作目录。
2. 不得使用保存项目的 `create_thread + worktree` 来假定继承当前任务的 dirty working tree；保存项目可能仍指向旧 checkout 或旧 HEAD。
3. 只有在用户明确需要隔离工作树，且改动已经提交，或已完成显式、逐文件、带哈希的迁移时，才创建独立 worktree。
4. 同目录任务共享文件，默认只允许一个任务写入；其他任务保持只读，避免并发覆盖。

## 3. 两阶段授权

### 阶段一：只读身份门

新任务的第一条消息只能要求检查，不得同时授权编辑、Git 写入、真实模型/API 调用、部署、删除或其他不可重复动作。必须返回：

- 实际 `cwd`；
- 实际 `HEAD`、分支或 detached 状态；
- host、project/thread 身份；
- `git status --short` 摘要或稳定指纹；
- 每个必需交接文件的存在性、大小和 SHA-256；
- 与源任务期望值的逐项比较。

父任务必须通过任务读取/等待工具独立核对这些结果，不能只信任子任务自报。

### 阶段二：执行授权

只有阶段一全部一致后，父任务才发送第二条消息授权代码编辑、真实模型调用或其他外部动作。一次性、付费、不可重放或高后果动作不得放在异步创建任务的初始 Prompt 中。

## 4. 失败关闭

任一身份项不一致、必需文件缺失或哈希不符时：

1. 立即停止，不执行编辑、模型调用或外部动作；
2. 将错误任务标记为“错误基线，请勿继续”；
3. 不得通过绝对路径转而修改源工作树；源路径只可用于只读取证；
4. 返回源任务，选择同目录 fork，或先完成可审计的文件迁移；
5. 已消耗的一次性调用按真实失败记录，不能因编排事故自动重试。

## 5. 本次事故证据

- 源任务：`dcef`，HEAD=`e92889c`，包含未提交的 V0.3/V0.4 文件。
- 错误新任务：`c4c3`，HEAD=`9d9cb01`，交接文件不存在。
- 错误任务在工作区验证前获得真实 T1 授权，并通过绝对源路径修改了 dcef、消耗了一次调用。
- 使用 `same-directory` fork 后，新任务实际 `cwd` 回到 dcef，可直接读取交接文件。

## 6. 验收检查表

- [ ] 创建方式与 dirty/untracked 状态相容。
- [ ] 初始 Prompt 只有只读检查。
- [ ] 父任务已核对新任务实际 `cwd/HEAD/status`。
- [ ] 必需文件存在且哈希一致。
- [ ] 新任务尚未编辑或执行真实调用。
- [ ] 第二阶段授权由父任务在验证后单独发送。

六项全部勾选前，新任务不得开始开发。
